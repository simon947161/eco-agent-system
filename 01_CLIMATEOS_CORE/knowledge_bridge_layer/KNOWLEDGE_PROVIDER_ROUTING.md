# Knowledge Provider Routing

## Purpose

Knowledge Provider Routing defines how future bridge architecture may decide
which provider or bridge path is appropriate.

## Routing Factors

- provider type
- knowledge category
- source authority
- access boundary
- update frequency
- citation requirement
- maturity level
- validation need
- runtime relevance

## Routing Examples

- GitHub for foundation documents.
- Obsidian for future knowledge garden notes.
- Local Markdown for portable documentation.
- MCP providers for future contextual resources.
- Enterprise systems for organizational knowledge.

## Boundary

No router, provider resolver, API, or automated retrieval logic is implemented.
