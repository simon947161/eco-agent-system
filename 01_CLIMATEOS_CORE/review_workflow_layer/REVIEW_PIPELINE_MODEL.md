# Review Pipeline Model

## Purpose

The Review Pipeline Model defines the conceptual order of review stages.

## Pipeline

```text
Observation
-> Knowledge
-> Evidence
-> Reality Claims
-> Cross Validation
-> Forecast Candidates
-> Confidence Update
-> Conflict Analysis
-> Revision
-> Integrated Review
-> Recommendation
-> Governance Output
```

## Pipeline Notes

The pipeline is not strictly linear in practice.

New evidence may reopen earlier stages. Conflict analysis may send a review
back to evidence gathering. Forecast validation may trigger confidence updates
or revision.

## Pipeline Inputs

Inputs may come from:

- Observation Layer
- Knowledge Runtime
- Evidence Assets
- Proof of Reality
- Forecast Planning Plugin Framework
- Earth Intelligence Interface
- EcoChain
- Collective Validation Layer
- Confidence Framework Layer

## Pipeline Outputs

Outputs may include:

- updated review position
- updated confidence state
- unresolved conflict
- request for more evidence
- recommendation candidate
- governance output candidate

## Boundary

No workflow runtime, queue, API, orchestration system, or automation is created.
