# Knowledge Version Model

## Purpose

Knowledge Objects should preserve version history so future agents and
contributors can understand what changed.

## Version Fields

- identifier
- version label
- creation date
- revision date
- source revision or commit if available
- change summary
- supersedes relationship
- deprecated status if relevant
- reviewer or maintainer if known

## Versioning Principle

Knowledge should be allowed to evolve without losing traceability.

## Boundary

This document does not implement version control beyond existing repository
history.
