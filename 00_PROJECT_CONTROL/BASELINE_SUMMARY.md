# ClimateOS Repository Baseline Summary

This page is the concise starting point for new contributors, reviewers,
future partners, and the repository owner.

## What Exists

- a project-control folder with roadmap, rules, task index, queue, templates,
  architecture decisions, and maturity guidance;
- a fifteen-part ClimateOS master directory scaffold;
- a manual Codex queue for task status, dependencies, review, and completion;
- an official Agent Standard, lifecycle, checklist, catalog, and templates;
- existing CCZPS-Lite deterministic runtime, evidence, review, reporting, and
  automated tests that predate this repository-control baseline.

## What Does Not Yet Exist

- implemented CarbonOS, EnergyOS, WaterOS, LandOS, BiodiversityOS, ParkOS,
  ESGOS, GISOS, ScenarioOS, ValidationOS, or GovernanceOS subsystem runtimes;
- operational agents in the new Agent Catalog;
- GIS/DEM processing in the new GISOS scaffold;
- payments, marketplace transactions, wallets, blockchain, or financial tools;
- autonomous approval, ranking, recommendation, scientific confirmation, or
  professional certification systems.

## Repository Structure

`MASTER_DIRECTORY_MAP.md` is the canonical map for the scaffold:

```text
Project Control
ClimateOS Core
Domain Subsystems
Scenario / Validation / Governance Layers
Business Planning
Demonstrations
Documentation
```

Earlier placeholder folders remain for backward compatibility and have not
been deleted or renamed.

## Control Systems

- `TASK_INDEX.md` records task purpose and status.
- `QUEUE_DASHBOARD.md` gives the operational overview.
- `QUEUE_STATUS.md` separates proposed, ready, active, review, blocked, and
  completed work.
- `TASK_DEPENDENCIES.md` records normal task order.
- `TASK_PIPELINE.md` defines lifecycle entry and exit conditions.
- `AGENT_STANDARD.md` defines future agent documentation requirements.
- `REPOSITORY_MATURITY.md` prevents scaffold folders from being mistaken for
  implemented capability.

## Future Development Areas

The next recommended development area is Task50, CarbonOS Foundation. It should
define evidence, accounting boundaries, uncertainty, validation, governance,
and interoperability before any executable carbon agent is created.

Later work may cover EnergyOS, WaterOS, LandOS, BiodiversityOS, ParkOS, ESGOS,
GISOS, demonstrations, and public documentation in small reviewed tasks.
