# Repository Roadmap

This roadmap describes proposed phases. A phase is not complete unless
repository evidence and task records explicitly show completion.

## Phase 0 - Repository Control Layer

**Purpose:** establish clear controls for tasks, architecture decisions, Codex
sessions, and future agents.

**Expected outputs:** project-control documents, task index, batch queue,
system directory scaffold, agent template, and architecture decisions.

**Example future tasks:** maintain the task index, refine batch rules, and add
review checklists.

## Phase 1 - ClimateOS Core Stabilisation

**Purpose:** clarify the reusable ClimateOS kernel while preserving existing
CCZPS-Lite evidence, governance, and reporting boundaries.

**Expected outputs:** stable minimal-core schemas, consolidated packs,
compatibility boundaries, and repeatable validation and release procedures.

**Example future tasks:** schema definitions, dashboard simplification,
compatibility tests, and a v0.6 release.

## Phase 2 - CarbonOS Foundation

**Purpose:** define a conservative carbon-accounting subsystem that reuses the
ClimateOS evidence and review model.

**Expected outputs:** CarbonOS scope, terminology, evidence requirements,
agent specifications, and governance boundaries.

**Example future tasks:** CarbonOS Foundation, Green Power Accounting Agent,
and Carbon Budget Agent.

## Phase 3 - EnergyOS / ParkOS / ESGOS Expansion

**Purpose:** define modular subsystem layers for energy evidence, zero-carbon
parks, and ESG disclosure review.

**Expected outputs:** subsystem architecture notes, reusable agent
specifications, evidence interfaces, and demonstration reports.

**Example future tasks:** ESG Disclosure Auditor Agent, Zero Carbon Park Agent,
and energy-evidence templates.

## Phase 4 - GISOS and Evidence Mapping

**Purpose:** plan governed spatial evidence integration without overstating
configured or planning-only GIS/DEM capability.

**Expected outputs:** GISOS boundaries, data requirements, provenance and
validation standards, review workflows, and connector plans.

**Example future tasks:** GISOS Foundation, spatial evidence schema, and
professionally reviewed mapping interfaces.

## Phase 5 - Demonstration Scenarios

**Purpose:** demonstrate how the shared kernel and subsystem agents can work
together on clearly bounded, human-reviewed cases.

**Expected outputs:** reproducible scenario inputs, evidence and review packs,
cross-system demonstrations, and limitation notes.

**Example future tasks:** Batlow, Datong, and Shanghai demo integration.

## Phase 6 - Documentation and Public Communication

**Purpose:** make the project understandable to non-programmers, partners,
reviewers, and contributors.

**Expected outputs:** user guides, architecture diagrams, release packages,
public demonstration narratives, and contributor onboarding material.

**Example future tasks:** public documentation audit, demonstration guide, and
versioned release communication.
