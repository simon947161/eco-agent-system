# Codex Operating Rules

1. Do not delete existing files.
2. Do not rename existing folders unless explicitly instructed.
3. Prefer small modular files.
4. Keep outputs human-readable.
5. Do not introduce new scientific claims.
6. Do not add GIS/DEM analysis unless explicitly requested.
7. Do not create approval, ranking, recommendation, or automated decision systems.
8. Do not add LLM/API integrations unless explicitly requested.
9. Run existing tests if available.
10. Provide a short completion summary.

Keep changes suitable for future ClimateOS, CarbonOS, EnergyOS, ParkOS, ESGOS,
and GISOS expansion. Treat each agent as a reviewable Agent Factory module.

## Required Task Format

### Purpose

Explain why the task is needed and who it serves.

### Scope

State what is included.

### Files to Create

List new files and their roles.

### Files to Modify

List existing files and the reason for each change.

### Acceptance Criteria

List observable completion conditions.

### Do Not Touch

Identify files, capabilities, and architecture outside the task boundary.

### Test Requirement

State the test command or verification.

### Completion Summary

List created and modified files, tests, and important limitations.
