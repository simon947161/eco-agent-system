# Task Pipeline

## Idea

**Purpose:** capture a possible improvement without committing repository work.

**Entry conditions:** a need, risk, or opportunity has been identified.

**Exit conditions:** the idea is either discarded, archived, or written as a
structured proposed task.

**Example:** "A CarbonOS evidence schema may be useful."

## Proposed

**Purpose:** document the task request and expected value.

**Entry conditions:** purpose and rough scope are known.

**Exit conditions:** dependencies, files, acceptance criteria, prohibited
changes, and test requirements are clear.

**Example:** Task50 is listed with a CarbonOS foundation purpose.

## Ready

**Purpose:** identify a task that can safely enter a Codex session.

**Entry conditions:** predecessors are reviewed, task format is complete, and
there is no known blocker.

**Exit conditions:** work starts or a new blocker is recorded.

**Example:** Task49 becomes ready after Task46-Task48 review.

## In Progress

**Purpose:** show the one primary task actively being implemented.

**Entry conditions:** a clean scope is confirmed and implementation begins.

**Exit conditions:** acceptance checks pass and the task enters review, or an
emergency-stop condition moves it to blocked.

**Example:** Task48 while its queue documents are being created.

## Review

**Purpose:** allow the repository owner to inspect scope, outputs, tests, and
limitations.

**Entry conditions:** implementation and required tests are complete.

**Exit conditions:** the work is approved, changes are requested, or rejected.

**Example:** locally completed Task46 and Task47 documentation.

## Completed

**Purpose:** record accepted work that meets its criteria.

**Entry conditions:** review is approved, tests pass, queue status is updated,
and a completion-log entry exists.

**Exit conditions:** none; later corrections should use a new task.

**Example:** an approved and logged repository-control task.

## Archived

**Purpose:** preserve old, replaced, rejected, or no-longer-relevant task
records without deleting history.

**Entry conditions:** a decision explains why active tracking is no longer
needed.

**Exit conditions:** a new task may reference the archive, but the archived
record itself is not silently reactivated.

**Example:** a superseded directory proposal retained for audit.
