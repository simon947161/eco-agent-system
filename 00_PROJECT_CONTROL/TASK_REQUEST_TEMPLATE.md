# Task Request Template

Submit future tasks using this structure. Keep one primary task per request and
make every boundary understandable to a non-programmer reviewer.

## Task ID

Use the next approved task identifier.

## Task Name

Use a short, specific name.

## Purpose

Explain why the task is needed and who it serves.

## Background

Describe relevant existing work, dependencies, and repository context.

## Scope

State exactly what the task includes.

## Files to Create

List each new file or directory and its purpose.

## Files to Modify

List permitted existing files and explain each modification.

## Acceptance Criteria

List observable conditions that prove the task is complete.

## Do Not Touch

List files, directories, capabilities, and architecture outside the task.

## Test Requirement

State the exact test command and any structural verification.

## Completion Summary

Require created files, modified files, tests, and important limitations.

Before submission, confirm dependencies in `TASK_DEPENDENCIES.md` and place the
task in the correct stage in `QUEUE_STATUS.md`.
