# Agent Name

## Purpose

Describe the narrow problem, intended users, and required reviewers.

## Inputs

List required and optional inputs, formats, units, provenance, and missing-data
behavior.

## Outputs

List human-readable and machine-readable outputs and their interpretation
boundaries.

## Evidence Requirements

Define evidence sources, confidence, uncertainty, traceability, currency,
quality, and review requirements.

## Runtime Fields

Define stable field names, types, allowed values, defaults, identifiers, and
versions. State `Not implemented` for a documentation-only proposal.

## Assumptions

List material assumptions, sources, owners, status, and failure conditions.

## Validation Rules

Define deterministic checks, invalid-input behavior, tests, and professional
validation needs.

## Governance Notes

Define human decision boundaries, resource and cost ownership, privacy, audit,
retention, and approval limits.

## Limitations

List missing capabilities and state what the agent cannot conclude or approve.

## Example Scenario

Provide a small labelled demonstration input and expected output. Preserve
uncertainty and avoid professional claims.

## Future Tasks

List incremental dependencies and extensions without claiming they exist.
