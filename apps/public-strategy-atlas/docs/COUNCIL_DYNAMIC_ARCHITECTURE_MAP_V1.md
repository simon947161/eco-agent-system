## 产品目标与真实能力

在原 Council 系统内建设真正可交互的网页动态架构地图作为新主界面，不是静态图、GIF、视频或独立演示系统。候选节点 Sources / Collection / Research / CSP-LSPS / Evidence / Reasoning / Verification / Delivery / Memory / Feedback 必须从真实结构确定；不存在的能力不能凭空添加。

使用有方向连线、沿线光点及反馈循环。节点可点击，在桌面上下文侧栏、手机底部详情展示模块说明、关联真实任务、状态、证据、成果、文件版本、阻塞和缺口。只有存在且有真实权限的功能才提供操作入口。

状态明确映射：未启动静态；排队轻脉冲；运行沿线光点；审批暂停；失败错误；完成未验收待验；通过完成；未知显示 UNKNOWN。禁止默认所有节点运行、用 mock 冒充生产。没有 live 接口时展示最后核实快照时间和非实时标签。教学或原型模拟动画必须明显标明模拟，并与真实状态隔离。

## 交互、技术与资产约束

兼容现有栈、尽量少依赖，优先 SVG 路径 + CSS。只有确有需要且现有架构允许，才评估 React Flow、Motion、WebSocket 或 SSE；不自动增加后端权限。应有真实动画、平移缩放、触控和点击。遵守 reduced-motion，关闭动画后全部功能仍可用。

桌面地图占主要视区、分组清晰、连线不混乱，保留全部现有入口以及任务和异常概览。手机使用节点聚焦、自适应布局及底部详情，不把桌面大图缩小挤字；必须实际浏览器验收。保持大字、清晰高对比、少滚动偏好。

研究、原文引用、文件、任务、审计、历史、owner-only 权限、模型及功能全部保留；不删减、不创建第二套权威数据。视图映射从既有权威模型派生。
