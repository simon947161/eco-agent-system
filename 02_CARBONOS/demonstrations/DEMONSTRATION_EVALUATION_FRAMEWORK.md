# CarbonOS Demonstration Evaluation Framework

## Purpose

This framework provides a common structure for CarbonOS demonstrations,
including Task57, Task58, and Task59. It keeps demonstrations reviewable,
human-readable, and reusable without adding calculations, runtime
functionality, or external integrations.

## How to Use This Framework

Each demonstration should complete the sections below. If a section does not
apply, state `Not applicable` and explain why. Do not remove sections.

## 1. Demonstration Name

Record the demonstration title, task ID, version, owner, and review date.

## 2. Scenario Description

Describe the demonstration context, boundary, time horizon, scenario type, and
purpose. State whether the scenario is baseline, alternative, target, risk, or
exploratory.

## 3. Inputs

List the input records, assumptions, evidence references, source documents,
scenario constraints, and known gaps. Preserve source status and uncertainty.

## 4. CarbonOS Agents Used

Identify which CarbonOS foundation agents are used conceptually:

- Green Power Classification Agent
- Carbon Accounting Agent
- Carbon Budget Agent
- Carbon Verification Agent
- ESG Disclosure Agent
- Carbon Scenario Agent

State clearly when an agent is referenced as a foundation document only.

## 5. Expected Outputs

Describe expected human-readable outputs, such as scenario notes, evidence
summaries, review packs, governance notes, disclosure-preparation records, or
lessons learned. Do not describe calculations or runtime outputs unless a
future task explicitly implements them.

## 6. Validation Considerations

Record evidence completeness, boundary consistency, assumption transparency,
traceability, uncertainty, missing information, and human review needs.

## 7. Governance Considerations

Record decision owners, review responsibilities, stakeholder context,
prohibited interpretations, confidentiality, and approval boundaries.

## 8. Lessons Learned

Summarise what the demonstration shows about CarbonOS structure, agent reuse,
evidence needs, scenario design, or governance requirements.

## 9. Reusability Assessment

Explain which parts can be reused by other demonstrations, future agents,
ClimateOS layers, ScenarioOS, ValidationOS, GovernanceOS, or EcoEngine
alignment work.

## 10. Future Development Opportunities

List possible future tasks, missing templates, validation needs, data-model
extensions, scenario packs, or controlled implementation opportunities.

## Framework Limits

- Documentation only.
- No calculations.
- No forecasting, optimisation, or recommendations.
- No reporting, compliance, assurance, or approval engine.
- No APIs, external integrations, or runtime functionality.
- Demonstrations must not be presented as operational CarbonOS capability.
