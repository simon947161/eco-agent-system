# Foundation Roadmap Stability Decision

## Purpose

This document records the permanent roadmap management principles for
ClimateOS Foundation development.

It protects the long-term foundation roadmap from unnecessary restructuring
while still allowing new ideas to be absorbed into existing milestones.

## Foundation Stability

Task100, Task150, Task200, and Task300 remain stable long-term milestones.

Major milestone objectives should not be rewritten simply because new ideas
appear.

## Evolution Rule

New concepts should normally be absorbed into existing tasks.

Prefer evolution over restructuring.

## Foundation vs Strategy

Foundation defines universal capabilities.

Strategy defines application domains.

These two layers remain independent.

## Domain Runtime Strategy

Infrastructure Governance becomes a strategic application domain.

It does not replace the Foundation architecture.

BuildingOS remains a future domain runtime.

CarbonOS remains the first major domain runtime after Foundation.

BuildingOS follows CarbonOS and integrates:

- CarbonOS
- WaterOS
- EnergyOS
- LandOS
- ClimateOS Review Engine
- EcoChain

## Development Constitution

Permanent principles:

```text
Stabilize milestones.
Evolve content.
Expand applications.
```

and:

```text
Architecture converges.
Strategy evolves.
Runtime expands.
```

## Practical Meaning

When a new idea appears:

- first check whether it fits an existing milestone
- preserve Task100 / Task150 / Task200 / Task300 objectives
- add supporting documents when needed
- avoid rewriting the foundation sequence
- distinguish foundation capability from domain strategy

## Boundary

This is a strategy decision only.

It does not implement runtime capability, APIs, governance automation,
blockchain, token models, or domain runtime systems.
