ClimateOS / CarbonOS has grown beyond a simple one-agent project workflow.

The current manual pattern is too heavy:

```text
Founder -> GPT discussion -> Codex task instruction -> Codex output -> GPT review -> Founder decision -> next Codex task
```

This pattern still works, but it requires too much manual supervision by the Founder. During Task131-140, the project spent excessive time managing Git, push, merge, safe.directory, approval/freeze, and admin process mechanics.

The Founder explicitly identified that this is not the desired way to build ClimateOS / CarbonOS.

The project needs a Project Runtime / MCP / multi-agent coordination layer so that:

- agents can communicate and cooperate;
- agent hierarchy is explicit;
- task handoffs are structured;
- approval gates are recorded;
- ethical, commercial, and responsibility boundaries are preserved;
- project context can move between threads and agents;
- the Founder is not forced to manually supervise every small technical step.

## 5. What PRI / MCP should solve first

The PRI / MCP thread should not begin with a giant implementation.

It should first create a clear architecture and rule system.

Recommended first deliverables:

### PRI-MCP-01: Multi-Agent Role Map

Define the role, authority, limits, and interaction pattern of Founder, GPT, Codex, QCloud, MCP server, and future agents.

### PRI-MCP-02: Task Handoff Protocol

Define how a task moves between:

```text
Founder -> GPT -> Codex / agent -> validation -> GPT review -> Founder gate -> archive
```

Include status labels such as:

- proposed;
- scoped;
- approved;
- in progress;
- blocked;
- completed;
- reviewed;
- frozen;
- closed;
- parked.

### PRI-MCP-03: Approval Gate Model

Define which actions require Founder approval:

- push / merge / release;
- QCloud re-entry;
- runtime implementation;
- MCP server implementation;
- external standards research authority;
- compliance / assurance / certification language;
- public disclosure;
- production API/database/scoring/automation;
- closure / freeze / architecture gate.

### PRI-MCP-04: Context Packet Standard

Define a reusable PCTP / context packet format for passing project state between GPT threads and agents.

Should include:

- project identity;
- current branch / repo;
- current status;
- last known commits;
- active tasks;
- frozen artifacts;
- boundaries;
- risks;
- next actions;
- CRP harvest;
- handoff instructions.

### PRI-MCP-05: Ethics, Incentive, and Commercial Runtime Rules

Define how the multi-agent system avoids:

- unauthorized claims;
- hidden commercial commitments;
- unsafe automation;
- false expertise;
- agent overreach;
- blurred responsibility.

Also define possible incentive / commercial logic for future project operation.

### PRI-MCP-06: ClimateOS Re-entry Plan

Define how ClimateOS / CarbonOS Task141-150 resumes after PRI / MCP v0.1 exists.
