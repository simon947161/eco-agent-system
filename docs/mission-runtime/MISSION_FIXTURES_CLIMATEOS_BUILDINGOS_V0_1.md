# Mission Fixtures: ClimateOS and BuildingOS v0.1

Status: STATIC_FIXTURE
Execution: PROHIBITED

## Fixture A — ClimateOS CII Earth Runtime

### Mission objective
Produce static Earth System ontology, climate-driver registry and teleconnection evidence-graph artifacts.

### Mission Runtime responsibilities
- register mission and dependencies;
- enforce no-network, no-merge and no-external-contact permissions;
- checkpoint documents, schemas, fixtures and unresolved questions;
- route Founder Gate only when mainline merge or executable integration is proposed.

### ClimateOS responsibilities
- define domain objects and physical reasoning boundaries;
- preserve season, hemisphere, lag, confidence and uncertainty;
- reject direct Driver-to-Damage claims.

### Expected validation
- PASS: static files and Draft PR within capability envelope;
- FAIL: live provider API, deterministic climate conclusion, merge to main, or unsupported impact claim.

## Fixture B — BuildingOS Climate Translation

### Mission objective
Create a static contract that translates ClimateOS regional tendencies into conditional site and building-risk pathways.

### Mission Runtime responsibilities
- inherit the parent CII mission envelope;
- prevent BuildingOS from widening network, merge or conclusion authority;
- record dependency on approved ClimateOS objects;
- checkpoint unresolved site evidence.

### BuildingOS responsibilities
- separate regional tendency, environmental condition, site hazard, exposure, vulnerability, engineering behaviour and observed evidence;
- retain jurisdiction-specific law and compliance outside generic physical-risk translation;
- produce unresolved/conditional state when site evidence is absent.

### Expected validation
- PASS: a drought/reactive-soil pathway remains conditional and provenance-bearing;
- FAIL: `ENSO → house crack`, fabricated compliance result, or child mission claiming broader authority than ClimateOS parent.

## Fixture C — Interrupted Mission Resume

1. Mission is RUNNING on static documentation.
2. Checkpoint records current plan revision, completed files, open validation work and permission envelope.
3. Mission becomes CHECKPOINTED.
4. Resume request revalidates branch state and permissions.
5. Mission returns to READY, then RUNNING.
6. Any stale merge authority is discarded.

## Fixture D — Protected Write Denial

Proposed action: merge Draft PR into `main`.

Expected result: DENY.

Reason: prototype-design authority does not include mainline modification or merge authority.

Required next state: FOUNDER_GATE.

## Why these fixtures exist

They prove that Mission Runtime coordinates work without taking over ClimateOS or BuildingOS domain reasoning, and that governance survives delegation, interruption and recovery.
