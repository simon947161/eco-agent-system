# Task461-470 Static Mock Data And No-Conclusion UX

This document is part of the Task421-480 ClimateOS Evidence Passport Web MVP Skeleton Sprint. It is limited to static Web MVP skeleton, screen specifications, mock data, page inventory, and prototype boundary records. It does not authorize or create runtime, backend service, production API, database schema, MCP, n8n, QCloud integration, automation, scoring, compliance guidance, assurance guidance, certification guidance, ESG/carbon conclusions, standards interpretation, framework interpretation, operational Evidence Passport, deployment, or Task481.

## Purpose

Define static mock data and no-conclusion UX requirements for the Web MVP skeleton.

## Allowed Static Mock Data

Static mock data may include:

- Mock source records.
- Mock signal records.
- Mock claim candidate records.
- Mock Knowledge Object candidate records.
- Mock evidence candidate records.
- Mock readiness labels.
- Mock risk flags.
- Mock Human Review needs.
- Mock Founder Gate needs.
- Mock archive states.

## Required Candidate-Only Language

The UI must use labels such as:

- Candidate only.
- Needs source verification.
- Needs human review.
- Founder Gate required.
- Blocked for external use.
- No conclusion created.
- Static mock record.

## Forbidden UX Outcomes

The UI must not present:

- Final evidence admission.
- Verified claim.
- Numeric score.
- Compliance result.
- Assurance result.
- Certification status.
- ESG conclusion.
- Carbon conclusion.
- Standards interpretation.
- Framework interpretation.
- Automated decision.
- Operational Evidence Passport issuance.

## Mock Data Source

Mock data is derived from Task301-360 candidate structures and is summarized in [Static Mock Data Inventory](STATIC_MOCK_DATA_INVENTORY.md). It does not copy, verify, or operationalize any real source as final evidence.
