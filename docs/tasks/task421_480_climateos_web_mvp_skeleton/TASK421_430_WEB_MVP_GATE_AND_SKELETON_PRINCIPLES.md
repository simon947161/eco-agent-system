## Skeleton Principles

| Principle | Meaning | Boundary |
| --- | --- | --- |
| Visible but non-operational | The workflow can be seen and reviewed. | No live workflow, backend, API, or database. |
| Candidate-only | All source, signal, claim, Knowledge Object, and evidence records are mock candidates. | No final evidence admission. |
| Human Authority visible | Human Review is represented as a review control. | No automated review or approval. |
| Founder Gate visible | Founder Gate is represented as a stop point. | No delegated Founder authority. |
| No-conclusion UX | Interface copy prevents conclusion creep. | No ESG, carbon, compliance, assurance, certification, standards, or framework conclusions. |
| Static mock data | Data is hard-coded for review. | No persistence, ingestion, live source intake, or external connection. |
| No scoring | Readiness and risk labels are labels only. | No numeric ranking or scoring logic. |
| Hard stop | Task480 is the sprint end. | Task481 requires separate Founder authorization. |

## Static Mock Data Rule

- Candidate-only status.
- Source traceability.
- Readiness label as non-scoring metadata.
