# Task652 Why Alpha Runtime Cannot Start Automatically

## Purpose

Explain why Alpha Runtime is a major gate, not the next automatic task.

## Plain-Language Explanation

Documentation can ask questions. A runtime can act on structures.

Once ClimateOS has runtime, it may store records, route tasks, present evidence,
coordinate humans, call models, support agents, trigger workflows, and shape
what users believe is ready for decision. That power is useful, but it also
creates risk.

Alpha Runtime therefore cannot start just because the documents are promising.
It needs a Founder decision after the system can explain what it will do, what
it will refuse to do, and how humans remain in control.

## Why This Matters

ClimateOS is not only a technical tool. It is an environmental governance and
evidence system. A premature runtime could:

- turn weak observations into apparent conclusions;
- make agent outputs look authoritative;
- hide uncertainty behind interface polish;
- mix human review, model output, and evidence without clear labels;
- create scoring or certification pressure before the science is ready;
- make private EcoEngine boundaries harder to preserve;
- encourage users to treat candidate reasoning as validated reality.

## Decision Principle

Alpha Runtime may be discussed only when ClimateOS can preserve:

- observation versus interpretation;
- hypothesis versus conclusion;
- evidence need versus evidence sufficiency;
- human review versus automated output;
- agent assistance versus agent authority;
- local prototype versus operational system.

## Current Capability

Task651-660 can define the decision gate. It cannot open it.
