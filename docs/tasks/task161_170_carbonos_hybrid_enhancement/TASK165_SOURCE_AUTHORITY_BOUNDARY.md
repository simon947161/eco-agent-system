# Task165 Source Authority Boundary

## Purpose

Task165 defines how source authority should be classified during official source discovery.

## Authority Classes

| Class | Description |
| --- | --- |
| Primary official source | Source published by the responsible standard setter, regulator, legal publisher, or framework owner. |
| Official guidance | Guidance published by the same official body or authorized source. |
| Official portal | Portal that routes to current versions or period-specific materials. |
| Official project / update page | Official page describing updates, amendments, consultations, or development status. |
| Secondary context | Non-official explanation, article, summary, consultancy note, or model memory. |
| Internal repository context | Prior ClimateOS / CarbonOS documentation. Useful for routing, not source authority. |

## Authority Rule

Future factual use must prefer primary official sources over official guidance, official guidance over secondary context, and official sources over internal repository memory.

Internal repository documents can explain why a source matters to ClimateOS, but they cannot substitute for source verification.

## Runtime Authority Risk

Runtime integrity depends on source authority because stale or secondary sources may create:

- false evidence freshness
- outdated claim confidence
- wrong reporting-period context
- incorrect version dependency
- misleading cross-framework mapping

## Boundary

This task does not approve any source as substantively correct. It only classifies authority level for future review.
