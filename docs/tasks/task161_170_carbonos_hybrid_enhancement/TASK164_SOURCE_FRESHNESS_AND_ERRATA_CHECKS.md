# Task164 Source Freshness And Errata Checks

## Purpose

Task164 defines freshness, amendment, errata, and update checks for official source discovery under the runtime lens.

## Freshness Checks

Before a source can support future intake, reviewers must check:

- access date
- publication date
- effective date
- version date
- amendment status
- current reporting period relevance
- official correction, errata, or update page
- related active or completed projects
- supersession or archived status

## Runtime Freshness Risk

Runtime-sensitive sources need stricter review when they affect:

- claim timing
- evidence freshness
- physical risk or extreme event context
- reporting period selection
- disclosure cycle version
- source hierarchy
- cross-framework alignment

## Stale-Source Warning

If currentness cannot be verified, future notes must use:

```text
STALE-SOURCE WARNING: DO NOT USE WITHOUT CURRENT OFFICIAL SOURCE CHECK.
```

## Errata And Amendment Log

Future source intake should record:

| Field | Purpose |
| --- | --- |
| Amendment locator | Official amendment, correction, or project page. |
| Amendment date | Date issued or effective if verified. |
| Affected source | Source or section affected. |
| Review status | Pending, reviewed, conflict, superseded, or rejected. |
| Runtime impact | Whether change affects freshness, evidence linkage, claim timing, or boundary review. |

## Boundary

This task does not determine whether any amendment changes a requirement. It only defines the freshness check.
