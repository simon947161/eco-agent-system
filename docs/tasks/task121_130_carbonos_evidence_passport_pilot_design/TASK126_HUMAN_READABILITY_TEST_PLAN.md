# Task126 Human Readability Test Plan

## Purpose

Task126 defines how a human reviewer checks whether the CarbonOS Evidence Passport and fictional pilot cases are understandable.

This is a documentation-only review plan. It does not create runtime capability, automated review, scoring, compliance determination, assurance determination, public disclosure, or operational authority.

## Review Scope

The readability test applies to:

- Task121 Post-Task100-120 Reconciliation
- Task122 Pilot Use Case Selection Principles
- Task123 Evidence Passport Pilot Case Template
- Task124 Fictional Pilot Case A
- Task125 Fictional Pilot Case B

Task126 does not draft or authorize Task129, Task130, Task131, or later work.

## Human Reviewer Role

The human reviewer checks whether a careful reader can understand:

- what is fictional
- what is non-operational
- what is being reviewed
- what evidence is available
- what evidence is missing
- what remains uncertain
- what expert review triggers are visible
- what recommendations mean
- what recommendations do not authorize

The reviewer does not decide whether any carbon, ESG, environmental, compliance, assurance, investment, construction, operational, or public disclosure claim is valid.

## Readability Questions

| Question | Expected answer |
| --- | --- |
| Is the case clearly labelled fictional, illustrative, and non-operational? | Yes |
| Can the reviewer identify the claim under review? | Yes |
| Can the reviewer distinguish raw data, observation, inference, evidence, claim, and recommendation? | Yes |
| Can the reviewer see what evidence is missing? | Yes |
| Can the reviewer see whether confidence is low, uncertain, or unresolved? | Yes |
| Can the reviewer identify expert review triggers? | Yes |
| Can the reviewer see that recommendations are not action authority? | Yes |
| Can the reviewer see that public disclosure is not authorized? | Yes |
| Can the reviewer see that compliance, assurance, investment, construction, and operation are not authorized? | Yes |

## Readability Outcome Categories

| Outcome | Meaning |
| --- | --- |
| Readable | The document can be understood by a careful human reviewer without extra explanation. |
| Partially usable | The document is understandable in parts but leaves important ambiguity. |
| Governance-ready for review | The document is clear enough for architecture or founder review, but not for operational use. |
| Failed / unsafe | The document could be mistaken for a real conclusion, authorization, disclosure, compliance result, assurance result, or operational decision. |

## Test Procedure

1. Read the document title and purpose.
2. Confirm the fictional / illustrative / non-operational label.
3. Identify the claim under review.
4. Check whether the evidence discipline categories are separated.
5. Identify missing evidence and uncertainty.
6. Review the expert trigger matrix.
7. Check whether recommendations are review-oriented only.
8. Confirm no operational, public, compliance, assurance, investment, or construction authority is implied.
9. Assign a readability outcome.
10. Record unresolved ambiguity for founder or architecture review.

## Failure Conditions

The readability test fails if a document:

- appears to validate a real carbon or ESG conclusion
- appears to support public disclosure
- appears to authorize compliance, assurance, investment, construction, operation, or approval
- hides uncertainty or missing evidence
- merges observation, inference, evidence, claim, and recommendation
- omits expert review requirements where triggers are present
- weakens the action-authority boundary

## Action-Authority Boundary

A CarbonOS / ClimateOS recommendation is not an action authority.

It may identify a possible next step, review requirement, or decision option, but it cannot authorize implementation, approval, construction, investment, compliance declaration, public claim, or operational action without the required human, expert, or governance approval.
