# Task122 Pilot Use Case Selection Principles

## Purpose

Task122 defines safe selection principles for future fictional or non-operational pilot cases in the Task121-130 CarbonOS Evidence Passport package.

This document does not select real projects, assess real claims, generate carbon conclusions, or authorize operational action.

## Selection Goal

Pilot cases should test whether the Evidence Passport is understandable, traceable, and governance-safe for human review.

They should not test market readiness, compliance readiness, investment readiness, assurance readiness, public disclosure readiness, or operational performance.

## Allowed Pilot Case Types

Future pilot cases may be:

- fictional
- illustrative
- synthetic
- clearly non-operational
- based on generic sector patterns without identifying a real company, site, customer, project, facility, supplier, asset, or disclosure

## Disallowed Pilot Case Types

Future pilot cases must not:

- use real company data
- use real project data
- use real customer data
- use real disclosure data
- use real site or asset data
- imply compliance validity
- imply assurance validity
- imply investment readiness
- imply construction approval
- imply public environmental claim readiness
- produce a validated carbon or ESG conclusion

## Evidence Discipline Selection Test

A safe pilot case must support separation of:

| Category | Pilot selection requirement |
| --- | --- |
| Raw data | Use synthetic or generic inputs only. |
| Observation | State only what the fictional record appears to show. |
| Inference | Mark interpretations as provisional. |
| Evidence | Explain what would be needed before evidence could support a claim. |
| Claim | Keep claims fictional and review-oriented. |
| Recommendation | Restrict recommendations to review needs or next-step options. |

## Expert Review Trigger Coverage

Across the full Task121-130 package, fictional pilot cases should exercise all 13 expert review triggers without making real decisions:

1. High uncertainty
2. Conflicting evidence
3. Low confidence
4. Missing critical data
5. Regulatory consequence
6. Engineering consequence
7. Safety consequence
8. Insurance consequence
9. Legal consequence
10. Financial consequence
11. Public-impact consequence
12. Irreversible or high-cost project action
13. Domain-specific technical judgment

If a fictional pilot activates any trigger, the case must state that expert review would be mandatory in a real case.

## Minimum Safety Criteria

A future pilot case is acceptable only if all criteria are met:

| Criterion | Required answer |
| --- | --- |
| Fictional or non-operational label is explicit | Yes |
| No real organization, site, customer, project, asset, or disclosure is used | Yes |
| Evidence categories remain separated | Yes |
| Recommendations are non-authoritative | Yes |
| Expert review triggers can be identified without resolving them | Yes |
| No compliance, assurance, scoring, investment, construction, or public-claim readiness is asserted | Yes |
| Human or expert review needs are visible | Yes |

## Rejection Criteria

Reject or rewrite a pilot case if it:

- reads like a real carbon conclusion
- names a real organization or project without explicit founder authorization and fictionalization controls
- frames a recommendation as permission to act
- makes compliance, assurance, scoring, or disclosure claims
- depends on runtime logic, automated decisions, calculators, APIs, databases, or operational systems
- weakens Task100-120 frozen boundaries
- requires QCloud dispatch during the suspension window

## Recommended Pilot Mix for Later Tasks

Task124 and Task125, if later approved, should use contrasting fictional cases:

- one simple case with missing evidence and low confidence
- one more complex case with conflicting evidence and governance-trigger escalation

This is a design recommendation only. It is not authorization to draft Task124 or Task125.

## Action-Authority Boundary

A CarbonOS / ClimateOS recommendation is not an action authority.

It may identify a possible next step, review requirement, or decision option, but it cannot authorize implementation, approval, construction, investment, compliance declaration, public claim, or operational action without the required human, expert, or governance approval.
