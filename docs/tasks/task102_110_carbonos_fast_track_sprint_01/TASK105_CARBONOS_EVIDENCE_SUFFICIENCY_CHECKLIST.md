# Task105 CarbonOS Evidence Sufficiency Checklist

## Purpose

Task105 defines a checklist for judging whether evidence is sufficient for a
specific CarbonOS claim review.

The checklist supports review discipline. It does not prove the claim, certify
the result, or replace expert review.

## Checklist

| Check | Question | Result |
| --- | --- | --- |
| Claim clarity | Is the claim specific, bounded, and reviewable? | Pass / Partial / Fail |
| Source provenance | Are evidence sources identified by producer, date, and origin? | Pass / Partial / Fail |
| Period alignment | Does the evidence match the claim period? | Pass / Partial / Fail |
| Boundary alignment | Does the evidence match the asset, organization, scope, and geography? | Pass / Partial / Fail |
| Method clarity | Are methods, assumptions, factors, or interpretations stated? | Pass / Partial / Fail |
| Completeness | Are material activity data, certificates, or supporting records present? | Pass / Partial / Fail |
| Conflict review | Are contradictory records disclosed and handled? | Pass / Partial / Fail |
| Uncertainty | Are gaps, uncertainty, and confidence limits visible? | Pass / Partial / Fail |
| Expert trigger review | Are expert review triggers identified? | Pass / Partial / Fail |
| Authority boundary | Is it clear that recommendations do not authorize action? | Pass / Partial / Fail |

## Evidence Sufficiency Categories

| Category | Meaning |
| --- | --- |
| readable | The evidence boundary is understandable, but sufficiency may not be proven. |
| partially usable | Enough structure exists to guide remediation, but gaps remain. |
| governance-ready | Evidence is sufficiently structured for human expert review and governance decision. |
| failed / unsafe | Missing or confused evidence could support an unsupported governance decision. |

## Automatic Failed / Unsafe Conditions

Mark the review failed / unsafe if any condition applies:

- The claim cannot be traced to source records.
- Observations and inferences are merged without distinction.
- Critical data is missing and not disclosed.
- Evidence conflicts are ignored.
- A recommendation is framed as approval, assurance, compliance, investment, or
  operational authority.

## Action Authority Boundary

A CarbonOS / ClimateOS recommendation is not an action authority. It may
identify a possible next step, review requirement, or decision option, but it
cannot authorize implementation, approval, construction, investment,
compliance declaration, public claim, or operational action without the
required human, expert, or governance approval.
