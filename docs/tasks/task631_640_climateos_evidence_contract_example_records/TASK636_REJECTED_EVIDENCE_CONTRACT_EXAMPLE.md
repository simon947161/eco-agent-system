# Task636 Rejected Evidence Contract Example

## Purpose

Show how a weak or unsuitable record can be preserved without being reused.

## Example Record

| Field | Example Value |
| --- | --- |
| Evidence ID | `EC-REJECTED-001` |
| Origin Domain | CarbonOS |
| Receiving Domain | GovernanceOS |
| Claim Type | Proposed carbon improvement claim |
| Source Type | Fictional unsupported statement |
| Source Status | Rejected |
| Method Context | No method, baseline, or review evidence |
| Spatial Context | Fictional office context |
| Temporal Context | Unspecified |
| Uncertainty | Evidence is insufficient and claim wording is unsupported |
| Review State | Rejected for claim use |
| Prohibited Reuse | No claim, disclosure, scoring, certification, model training, or public use |
| Cross-Domain Notes | GovernanceOS should preserve rejection reason for auditability |

## Rejection Reason

The record attempts to support a carbon improvement claim without evidence.

## Interpretation

Rejected records still matter because they prevent repeated reuse of weak
claims and preserve why a claim was not accepted.

## Validation Requirement

Future review should decide whether rejected records can be resubmitted with
new evidence or must remain closed.
