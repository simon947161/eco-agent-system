# Task152 Official Source Registry Scaffold

## Purpose

Task152 defines a scaffold for tracking official sources for future CarbonOS standards research.

This is a documentation-only scaffold. It is not a database, data file, spreadsheet, registry implementation, API, runtime, or automation.

## Source Registry Purpose

The source registry scaffold exists to help future researchers record:

- which official sources need review
- which sources have been located
- which citation metadata is complete
- which versions are current or uncertain
- which framework or jurisdiction context applies
- which review state applies
- whether the source is eligible for future factual use

It does not record factual interpretations of standards.

## Source Categories

Future sources may be categorized as:

- primary official source
- official guidance
- official consultation or explanatory material
- regulator notice
- framework owner update
- superseded source
- candidate source
- source needing verification
- secondary context source

## Official Source Priority

Official sources have priority over secondary summaries, internal notes, memory, model recall, and prior repository documentation.

If an official source cannot be verified, future work may create only a placeholder and review rule. It must not create factual standards content.

## Source Metadata Fields

A future source registry entry may include:

| Field | Purpose |
| --- | --- |
| Source label | Short reference name. |
| Source title | Exact official title when known. |
| Source owner / publisher | Responsible body or framework owner. |
| Source category | Official source, guidance, notice, candidate, or other category. |
| URL / locator | Stable location if available. |
| Framework / jurisdiction label | Research context only. |
| Publication date | Date published when known. |
| Version date | Version or revision date when known. |
| Access date | Date accessed by researcher. |
| Citation status | Missing, partial, complete, or review needed. |
| Review status | Current review state. |
| Freshness status | Current, stale risk, unknown, superseded, or conflict. |
| Notes | Uncertainty and limitation notes only. |

## Publication Date / Version Date / Access Date

Future source entries must distinguish:

- publication date
- effective date if available
- version date if available
- access date
- review date

If these dates are missing or unclear, the source must be flagged before any future use.

## Jurisdiction / Framework Label

Jurisdiction and framework labels are research-routing metadata only.

They may include labels such as IPCC, ISSB, IFRS S2, ASRS, TNFD, China, EU, US, or other future frameworks, but this task does not explain or compare them.

## Citation Status

Allowed citation statuses:

- Not Started
- Source Needed
- Source Located
- Citation Partial
- Citation Complete
- Citation Review Needed
- Citation Rejected
- Superseded

## Review Status

Allowed review statuses:

- Placeholder
- Research Target
- Official Source Check Needed
- Version Check Needed
- Freshness Check Needed
- Founder / GPT Review Needed
- Eligible For Future Claim Review
- Rejected / Superseded

## No Factual Interpretation Yet

Task152 does not create:

- factual standards explanations
- standard-specific comparisons
- compliance interpretations
- method conclusions
- formula conclusions
- evidence conclusions
- jurisdictional conclusions

It creates only a scaffold for future source tracking.

## Task153 Handoff

Task153 may define citation, freshness, versioning, contradiction, stale-source, and no-source rules for future standards-related facts.

Task153 must not fill the source registry with factual standards content.
