# Task155 Factual Claim Review Workflow

## Purpose

Task155 defines how any future factual statement about standards becomes eligible for use in CarbonOS documentation.

This task creates a review workflow concept only. It does not create factual standards statements, execute research, approve claims, automate workflow, or implement a review system.

## Claim Proposal

A future factual claim proposal must include:

- proposed claim text
- framework / jurisdiction label
- intended use
- source citation
- version and access date
- uncertainty note
- limitation note
- proposer
- review owner

No proposed claim is usable by default.

## Source Attachment

Every proposed claim must attach source metadata:

- official source title
- source owner / publisher
- URL or stable locator
- publication date
- effective date if available
- version / revision date
- access date
- section / paragraph / page / table locator

If source attachment is incomplete, the claim is rejected or returned for revision.

## Citation Review

Citation review checks:

- whether the source is official or eligible
- whether citation metadata is complete
- whether the specific locator supports the proposed claim
- whether paraphrase wording stays narrow
- whether quoted text is minimal and necessary

## Freshness Review

Freshness review checks:

- access date
- version date
- possible supersession
- current official source availability
- stale-source warning status
- need for re-check before reuse

## Contradiction Review

Contradiction review checks:

- conflicting official sources
- superseded sources
- inconsistent secondary summaries
- unresolved interpretation risk
- scope mismatch

If contradiction exists, the claim cannot be promoted until reviewed.

## Founder / GPT Review

Founder / GPT review is required before a factual standards claim is eligible for CarbonOS architecture use.

The review must confirm:

- source traceability
- narrow wording
- non-authoritative status
- no compliance / assurance / certification claim
- no real-world conclusion
- appropriate uncertainty and limitation notes

## Approval Status

Allowed approval statuses:

- Proposed
- Source Attachment Incomplete
- Citation Review Needed
- Freshness Review Needed
- Contradiction Review Needed
- Founder / GPT Review Needed
- Eligible For Future Documentation Use
- Rejected
- Superseded

Eligibility does not authorize operational use.

## Rejection Status

Reasons for rejection may include:

- no source
- non-official source only
- incomplete citation
- stale source
- unresolved contradiction
- overbroad claim
- compliance implication
- assurance implication
- certification implication
- real-world conclusion implication

## Revision Handling

Rejected or incomplete claims may be revised only by:

- narrowing claim language
- adding official source citation
- updating version and freshness metadata
- resolving contradiction
- adding uncertainty notes
- rerouting to Founder / GPT review

## Task156 Handoff

Task156 may create a blank comparative method mapping template for future source-backed method comparison.

Task156 must not fill the template with real standards content or factual claims.
