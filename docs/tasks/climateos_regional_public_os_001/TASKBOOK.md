## 1. 使命与最终成果

建设面向大众的 ClimateOS 区域环境智能网站：让公众、研究者和地方管理者能够理解 Snowy Monaro 正在发生什么、证据是什么、物理机制如何成立、哪些结论尚不确定、有哪些可讨论的管理选项，以及行动后如何验证效果。

以 Council 为标准治理节点，以集水区、城镇、生态系统、资产和观测站为相互连接的地方对象；首个研究区域是 Snowy Monaro，首批地方上下文包括 Cooma、Berridale、Jindabyne 和 Snowy Mountains。Council 行政范围不能代替集水区、供水服务区或气候模型网格。

厄尔尼诺是第一项持续跟踪的使命案例，不是预设答案，也不是平台唯一主题。核心科学问题是：全球气候驱动经由哪些区域过程和地方物理条件，影响水、雪、土地、生态和基础设施？什么证据支持管理行动，什么证据会推翻原来的判断？

最终交付必须同时具有：

1. GitHub 中可追溯的源码、方法、任务、测试和发布记录。
2. 在 ChatGPT Sites 上可实际使用的网站，以及独立于浏览器打开状态的数据更新流程。
3. 从来源到图表、结论、管理选项和结果复核的完整证据链。
4. 能交给后续 Codex 会话继续执行的状态记录与操作手册。

这里的“操作系统”指持久、交互、可维护的研究与治理工作平台；不能用一个静态宣传页或未经验证的聊天机器人冒充完整交付。

## 7. 第一项科学使命：厄尔尼诺—雪山—地方水务

把2026-10-22前后讨论中的说法转成 Claim，不直接写成产品真相：

1. 厄尔尼诺的当前状态、峰值预测与历史排名。
2. 事件后“更冷”究竟相对于上一年、气候基准，还是长期趋势。
3. 地方均温、最低温、霜冻日、季节降雨、干旱和积雪变化。
4. 水文变化与用水、旅游季节、污水运行之间可能的联系。

物理解释至少覆盖：海气耦合和环流影响、地形与雨影、降水相态与海拔、积雪积累/消融、土壤蓄水与蒸散、降雨—径流—储水过程、设施暴露与服务需求。每条箭头记录机制、尺度、时滞、关键变量、文献、替代解释及反证条件。

可使用水量平衡 `ΔS = P + Qin − Qout − ET − W ± 其他明确通量` 作教学和研究框架，但各项必须对应相同空间边界、时间和单位，分别说明取水、回流、地下水交换；缺少关键数据不得假装闭合水量平衡。指数相关图不是物理机制证明。

最低验证规范：

- 缺测、迁站、仪器/观测时刻、质量码和异常值检查；不无声填补。
- 预先声明样本期、基准、统计假设与地区代表性；趋势及区间处理自相关、小样本和多重比较。
- 保存预测 vintage；历史回测只使用当时可获得信息，防止未来数据泄漏。
- 与气候平均、持续性或季节基准比较；概率预测使用适当的 Brier/校准等指标，连续变量使用适当误差指标；数据不足显示无法评分。
- ENSO、IOD、SAM 与长期趋势共同考虑，相关关系不写成因果结论；不得仅选支持观点的年份。
- 雪深不规则观测可能漏峰；雪季阈值、缺测和年际覆盖必须公开。
- 2026事件未来结果尚不可验证，先做历史回测和前瞻登记，等对应时段结束再评分。
- “Spencers Creek 最大雪深趋势”不等于地区年降雪总量；历史降幅不得线性外推成下一年预报。

交付一份真实数据、可复算的地方研究；如果数据受限，交付已经完成的部分和精确缺口，而非用合成结果代替。合成数据只用于测试与演示并醒目标识。

## 8. 公众网站的信息与交互

英文为默认公共语言，提供中文切换；用语清楚，地点、单位、时间和翻译保持一致。移动端可用，键盘可操作，颜色不是唯一状态提示。

核心页面/功能：

1. **区域首页**：最新更新、可信度/有效期、当前研究问题、数据覆盖与缺口；不制造没有数据支持的综合风险分数。
2. **地图与地方系统**：Council、集水区、站点和城镇分层；图层许可、来源、日期与比例尺。没有获准几何时使用明确标注的示意图，不能冒充地图。
3. **气候与雪水观察台**：可缩放时间序列、季节/基准切换、缺测和初步数据标志；显示原始或衍生序列须符合许可。
4. **判断核查页**：每条 Claim 的支持、冲突、未知、有效期和修订历史，一键追到来源与分析运行。
5. **物理机制与情景实验室**：解释机制，比较可调整参数与情景；明确教学示例与经验证模型的区别，不用滑块生成伪精确风险。
6. **RADAR**：研究/政策信号、待核问题、到期复核和关联证据；政策变化不自动升级为法定义务。
7. **治理机会页**：谁受影响、已核实责任、待确认负责人、现有措施、选项、成本/收益范围、依据、反对证据、停止条件和复核指标。
8. **公众提问与贡献**：带证据链接的问题、纠错和地方观察；提交后私有待审阅，未经同意不公开身份/精确位置，不自动采信或即时发布。
9. **Evidence Commons**：仅公开获准对象和许可允许的证据；支持版本、撤回、过期及下游影响追踪。
10. **研究与运行状态**：方法、代码版本、最近成功抓取、来源故障、已过期结论、任务进度和服务边界；公众状态不泄露日志密钥或个人信息。

自然语言问答只能回答已准入证据，给出来源、范围和有效期；证据不足须说明。首版可用结构化检索，不强制购买 LLM API。模型输出是草稿，不能自行制造来源或绕过审阅。

“完整互动”至少意味着选择地区/时段后图表与证据同步变化、可查询历史结论、可展开机制、能提交问题并得到真实持久化状态；不是按钮装饰或写死数字。

## 9. 自动运行、存储与部署架构

采用解耦方案：GitHub 保存源码与方法；数据采集/科学计算产生版本化公开安全数据包；Sites 提供公众界面、检索和受控写入。先用现有适配器和最小依赖，不要求重写全部 Python。

Sites 服务运行在 Worker 环境，不能假设能运行 Python、原生 GIS 或重型模型。Python 科学批处理在适用且有权限的 runner 上完成；较大数据或计算通过供应商中立 HTTP 任务接口处理。Worker 只执行适合其实际资源限制的功能。

根据当前 Sites 技能选择持久存储（例如 D1 元数据、R2 合规对象）与鉴权。Sites 托管源码仓库与公开 GitHub 仓库分别记录精确 commit 和内容/产物摘要；不得假称二者天然同步。每次发布保存 GitHub commit、Sites 源 commit、archive digest、版本和部署结果。

自动更新默认节奏（可配置）：

- 每日07:30 Australia/Sydney：检查获准的气候、水文、政策源及失败重试；不是所有来源每日生成新观测。
- 雪季每周：核查新雪深观测；非雪季仍保留可用记录，不捏造更新。
- 每月最后一天：建立当月研究周期、缺口、预测—实际对照和待审阅摘要。
- 每季度：生成治理机会与研究质量复核草稿。
- 每年：在保留缺失月份的前提下生成年度连续记录。

按来源限制降低频率，使用 ETag/Last-Modified、超时、大小限制、受控重定向、退避和重试；保存许可允许的最后成功快照。任务幂等、加锁、有重试上限；失败不覆盖有效旧版本，不把无数据变成零；界面显示过期和降级状态。

建立带版本的 unattended update writer 和服务身份；浏览器 localStorage、开发机开机、页面轮询或个人聊天保持打开都不算自动运行。Sites 原生定时能力若不可用，可用适用的 GitHub Actions 等替代，但必须实际验证凭据、持久化写入与读取。只选一个主调度入口，避免重复执行。

首次创建调度前检查已关联任务。至少执行一次真正的无交互作业，读回运行记录及数据变化，再验证断源、幂等重跑和恢复。保存调度配置只证明定时任务建立，不等于后台运行成功。

自动化可以更新获准来源事实及已验证方法产生的描述指标；新的 L3 解释、权限变化或高影响建议进入审阅队列。过期结论自动标记或降级，不自动升级权威。通知只在实质变化、运行失败或需要人处理时发给所有者，不发送无变化日报或对外机构消息。

## 10. 身份、审计与公共发布

角色至少为 public reader、contributor、researcher、reviewer、publisher、admin；服务账户只具必需写权限。服务器端做鉴权，不依赖隐藏按钮。公开读取与管理写入分离。

所有公众输入视为不可信数据，不能作为代理指令；限制大小、频率、HTML/脚本、任意 URL 抓取和批量上传。防止 XSS、CSRF、SSRF、越权、身份冒用、密钥泄漏和公开提交垃圾信息。

自动化产物保留审计链和备份；哈希证明一致性不等于独立真实性或不可篡改。按实际实现说明身份、签名与信任模型。撤回不悄悄删除历史，公开内容需要依法删除时记录不含敏感原文的撤回事件。

公共发布是本任务的最终目标，已获授权；先 owner-private 验证，再在能力与公开内容通过验收后发布公众读版。不得公开私有工作记录、内部数据库或未获许可内容。正式安全警报、工程/法定决策、机构背书和代表 Council 行动不在本任务授权内。

## 13. 测试与最终 Definition of Done

至少包含以下有意义的测试与证据：

- 数据：缺测、质量码、单位换算、基准变更、重复记录、源修订、时区/月末/闰年。
- 科学：已知可计算例子的正确结果、预测 vintage 防泄漏、基准比较、样本不足、相互依赖来源、空间错配拒收。
- 证据：图表点→数据版本→解析器→来源与许可→分析运行→限时答案；冲突和撤回向下游传播。
- 权限：跨节点/跨角色越权、私有字段公开泄漏、贡献待审阅、服务凭据、非可信内容处理。
- 运行：断源保留最后成功版本、幂等、部分失败、暂停/恢复、任务过期、备份恢复、部署回滚。
- 界面：桌面和手机、键盘操作、语言切换、真实交互、错误和空状态、来源链接与时间一致。
- 回归：运行项目要求的现有相关检查；现有测试会改写 tracked output，先隔离并检查副作用，不提交无关生成物。

全部最终交付满足：
