# 从 Snowy Monaro 现场学习到 ClimateOS：三条研究主线

研究日期：2026-10-26，Australia/Sydney。定位：个人学习、公开资料研究与机会假设检验。建议为暂定研究组合，不代表 Council 决策、科学因果结论或商业可行性认定。

## 1. 建议先做什么

建议把未来两年的核心问题收敛为：**在气候与增长不确定性下，区域如何以可负担的全生命周期成本，维持水、土地生态和基本服务，并留下可以复核的决策证据？**

投入三条主线：

1. **T1 水务韧性与水—能—碳：**以供水、污水、需求、维护、能源和排放的边界理解为专业锚点。
2. **T2 土壤—植被—流域韧性：**研究干旱适应、地表覆盖、水土过程、农业生产与生态的共同收益和代价。
3. **T3 区域证据与情景研究：**把 CSP 的公共结果、LSPS 的空间路径、指标与假设连接起来，让另两条主线的判断可重算、可质疑、可修正。

三者组成“基础设施—景观—证据”的研究组合。先形成框架，再通过一两年现场学习逐步验证。十年用于拓展案例、合作和长期结果，不用于等待基本框架成形。**理解整个 CSP 可以立即开始；声称能够管理整个 CSP，需要组织授权、数据治理、资源和政策责任，本次不作这一跃迁。**

建议个人研究时间初始按 T1 50%、T2 25%、T3 25% 分配，每季按证据调整。这是工作量假设，尚未了解你的每周可用时间；前 90 天以每周 3–5 小时为试行上限，若影响本职学习或休息则缩减。

## 5. 三条主线的证据设计

### T1：水服务、能源和排放的共同边界

核心假设H1：需求管理和能效维护可能在部分情景下，以更低全生命周期成本达到相近服务韧性。这里的“可能”需要对照检验，不能由CSP措辞推出。

先建立系统图：降雨/来水→取水与储存→处理输配→使用→污水收集处理→合规排放或经验证再利用；另画能源、维护、人力和资金流。Backflow与LTW的现场学习帮助理解“危害—控制—证据—责任”，但设备检查结果并不证明水系统整体能力。

建议指标：分别计算供水与污水的kWh/kL、年度与尖峰需水量、公开可得的漏损/断管率、服务中断、服务支出、家庭负担。供水和污水分母不同，不合并强度。单位排放使用适用年份、地区和核算范围；需区分购电、工艺CH4/N2O、燃料与隐含碳，不把购电节约当成总系统减排。NGA Factors可用于一般估算，但不能自动当作NGER合规方法。[NGA Factors 2025说明](https://www.dcceew.gov.au/climate-change/publications/national-greenhouse-accounts-factors-2025)

验证顺序：先复算一个公开基准；再比较无干预、节水维护、扩容和能效方案；最后由独立水务/工程人员检查边界与可行性。若保守价格、维护和替换成本下优势消失，应接受假设失败，而非寻找更乐观情景。项目经济量化前先获取实际成本与折现假设，本次不提供虚构NPV。

### T2：景观过程、农业与旱地生态

核心假设H2：改善地表覆盖、河岸和土壤管理，在特定土地条件下能提高抗旱或生态表现，且不以碳信用收入为前提。

单元应是流域/子流域或经许可的独立试验单元，明确土类、坡度、土地利用、降雨和管理历史。遥感覆盖只能筛查变化；土壤水分、侵蚀、入渗、生产量和土壤碳各有不同测量方法。恢复植被可能增加蒸散，不能承诺同时增加所有生态指标与下游水量。

建议设计：干预前后与相似对照比较（BACI思路）；先用公开历史数据检验对照可比性。若缺少独立场地和合作者，首年只做观测可行性与文献证据，不做因果宣称。1–2年可检验数据链和部分覆盖/水分响应，难以可靠证明多年土壤碳增量和长期生态韧性。不能把短期“变绿”写成增碳认证。

[DCCEEW土壤碳方法页面](https://www.dcceew.gov.au/climate-change/emissions-reduction/accu-scheme/methods/estimation-of-soil-organic-carbon-sequestration-using-measurement-and-models)在2026-08-04更新中记录了保守性问题和拟议调整；页面咨询截止日已过，研究日仍须另核最终法律/补充文件，不把拟议上限当已生效。另有[CER永久性义务](https://cer.gov.au/schemes/australian-carbon-credit-unit-scheme/how-to-participate-accu-scheme/permanence-obligations)。这支持暂不依赖碳信用作为创业基本收入。

### T3：把不确定性变成可检验记录

核心假设H3：来源锁定、明确口径与假设版本，能改善研究复核效率，同时避免AI把相关性、政策意图和场景算术混写成事实。

每条研究主张都绑定原文定位、来源版本、支持和反证、地理/时间范围、可用与禁用用途、复核状态。每个情景另存假设参数、计算方法、软件版本和Run Receipt。政策更新使旧映射待复核，不覆盖旧结论。AI可以提出问题和整理草稿，领域人员判断证据适用性，授权机关保留正式决策。

最低指标：主张可追溯比例、原文定位正确率、时间/空间/单位错误数、未解释冲突数、复核耗时、返工率、版本重开成功率。初始验收目标：样本10条全部可定位，关键单位/年份错误为0；效率改善目标暂定30%，经人工基线测量后调整。这些是**拟定门槛**，本次未完成真实用户或专家试验。

| 5–10年 | 有连续证据再讨论区域协作网络、旱地生态示范与长期资金 | 长期结果、独立治理、场地/知识权利、可负担维护 | 不以融资或平台规模代替环境效果；没有可持续责任主体则不启动综合场地项目 |

职业机会是工程/合规语言、GIS、证据和跨系统沟通能力；研究机会是可复核案例与合作；产业机会才涉及付费与组织责任。三者应分别验证，不能以本职接触到的困难直接转换成私人销售线索。优先考虑公开教育、非监管关系地区的独立研究与合规的跨地区合作，仍需雇主政策核定。

## 7. 数据与利益冲突隔离

设三种环境，不靠一个表里的“隐私标签”解决：

1. **Council正式环境：**客户、地址、设备、检查、投诉、内部GIS、运维、工作照片、录音及内部推断全部留在Council批准系统。个人ClimateOS没有接入、同步、上传或反向写回路径。真实信息即使删除姓名，也可能被位置、时间和设备组合重新识别。
2. **个人公开研究环境：**只使用核验过的公开资料、合成样例和抽象学习内容；公开不等于可任意再分发，逐来源记录许可、引述与归属。本次原型属于这里。政府公开统计与政府内部数据必须分开。
3. **未来私人合作环境：**须先解决数据所有权、合同、许可、最小采集和保存期，独立存储/账号/密钥/访问权限；本项目规则不允许真实客户或保密信息进入当前空间。不得将未来私人数据回流当前研究项目，也不得与Council记录拼接。

当前SMRC Code of Conduct（250.2016.1.5，2025-08-21）5.24要求相关或可能冲突的有偿外部工作书面通知CEO并取得书面批准；5.27涉及职责冲突、保密信息与Council资源、工作时间及疲劳等限制。[现行公开Code，PDF第18–19页](https://www.snowymonaro.nsw.gov.au/files/assets/public/v/5/council/policies/250.2016.1.5-policy-code-of-conduct.pdf)

应在任何商业试点前，通过正式渠道核定实际、潜在和可感知冲突；记录回避安排与复审触发，不向受本人监管、检查、许可或采购影响的对象推销。与雇主核清私人设备/时间、代码及研究IP边界。公开资料研究不等于已获准开展相关有偿业务。本次没有核实雇佣合同、内部兼职程序或取得批准，具体行动以Council正式要求为准。[ICAC外部工作风险说明](https://www.icac.nsw.gov.au/prevention/basic-standards/outside-employment)

## 9. 软件最小结构及交付状态

对象关系：`SourceVersion → Claim → Hypothesis → Metric / ScenarioRun → Opportunity → HumanReview`。反证和缺失证据为独立引用；不是一条全自动推理链。EEO负责环境证据；研究扩展增加规划映射、比较矩阵和机会检验记录，避免与现有Evidence Passport争夺权威。

| 对象 | 必要字段/规则 | 本次 |
|---|---|---|
| SourceVersion | 发布者、URI、发布日期、获取日、版本、定位、许可状态、哈希/未锁定、复查日 | 原型来源记录；仅CSP拥有原件实测哈希；完整发布者/许可等见研究来源表，生产schema待补 |
| Claim | 主张原文/释义、类型、来源ID、范围、限制、复核 | 已有；空链和重复ID拒绝 |
| Hypothesis | 支持、反证、缺口、失败条件、版本 | 已有；反证是挑战线索，不自动表示命题为假 |
| Metric | 数值或null、单位、边界、时期、方法版本 | 已有；缺失不补零 |
| ScenarioRun | 参数、单位、方法、数据类别、结果与排除项 | 仅合成供需/购电算术，不是气候/水文模型 |
| Opportunity | 使用者/购买者假设、关联问题、下一检验、冲突状态、阶段门 | 已有；始终研究状态，无自动商业放行 |
| Receipt与版本账本 | 输入摘要、来源记录摘要、结果摘要、可重开版本 | 已有；本地侧车，不是正式不可篡改系统 |
| HumanReview | 审查者角色、审查对象与版本、决定、理由、时间、重开条件 | 沿用上游；本次保持待审，不伪造人工完成 |

已交付代码和样例在 `prototype/`。11项自动检查覆盖引用、缺失、单位、NaN/无限/布尔误入、隐私类别拒绝、版本变化、账本修改检测、机会门和原月度模块重开。已运行扩展并生成结果。合成压力测试从120 ML需求/90 ML可用供应的30 ML缺口，在假设15%节水后变成12 ML；这一算术示例不代表Cooma或SMRC实际水量。能源参数和排放因子均为合成，不是NGA实参。
