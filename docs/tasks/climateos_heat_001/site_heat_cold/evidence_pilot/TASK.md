# HEAT–001｜工业冷热联供真实运行证据与 API 研究代理试点

接续 #189、#190（8101d81be403ddaf45f7cbd9fe80081bf63baeb0）及 #191（6bd7b640736ebe3d6dd0703bfa3dad04e9778e3d），独立草稿交付。

## 工程问题
食品厂负荷下降或用热错班后，实际能利用多少热？哪些记录足以比较直接换热、跨班储热与原锅炉？可推翻的预期为：若运行时长是回收热量变化的主要算术来源，其分解贡献应超过功率变化；若工厂分时数据不具备同期等服务对照，则保留因果缺口。

## 工作包与验收
1. Codex 自行寻找公开运行报告和有明确许可的机器可读数据。登记作者、版本、链接、许可、计量边界、原始字节摘要或明确标为报告转录。优先澳洲食品厂，其他场地只独立分析。
2. 清洗并复算。区分逐时值、典型小时均值、年化估计和持续时间。保存原单位、缺失、时钟、重复、转换、拒收理由。以 Hardwick 两期功率和小时分解热量变化，以另一工业数据集验证负荷或时间分布。用独立算式及失败用例验证。不得把不同场地拼成一个反事实。
3. 判断等产量、冷端温级、热水质量与时间、备用燃料和新增用电的覆盖情况。真实三臂节能、净碳、储罐投资与峰值调度各自给出证据状态。#191 稳态距离及污水甲烷仅作方法接口，#187 与现场设备维持冻结。
4. 构建最小研究代理接口，支持限定问题、受控只读检索、计算复跑、费用与次数上限、可审计输出、失败停止。模型可提出候选，确定性程序承担计量与计算。离线验证代理流程；生产密钥、预算和全系统迁移留给后续组织 Project。
5. GitHub 交付包括领取确认、独立分支与 Draft PR、输入与来源、清洗/计算脚本、运行回执、中文决策纪要。证据不足时列明缺失字段、下一笔数据能区分的工程选择。
