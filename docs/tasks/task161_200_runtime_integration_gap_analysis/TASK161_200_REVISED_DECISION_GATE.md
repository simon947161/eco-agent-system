## Purpose

This document records decision options for how the Task161-200 Baseline v1.0 route should proceed after the runtime-integration gap analysis.

It does not start Task161-170, modify the baseline sequence as approved execution, or implement runtime capability.

## Decision Options

### Option A: Keep Task161-170 As Official Source Discovery With Runtime Lens

Proceed with the preserved baseline sequence:


### Option B: Insert Runtime Integrity Integration Before Official Source Discovery

Create a separate runtime-integrity integration batch before source discovery.

Create a shared primitive batch for claim confidence, claim boundary evolution, evidence timelines, and review triggers.

Risk: this may prematurely expand ClaimOS before source discovery and framework intake.

### Option D: Defer All Runtime Integrity Work Until After Task200

Continue Task161-200 exactly as originally framed and defer runtime integrity until after evidence-based comparative reasoning prototypes.

Risk: future templates may need rework because runtime relevance fields were not captured early.

## Recommended Option

Recommended option:

```text
Option A: Keep Task161-170 as Official Source Discovery with runtime lens.
```

## Rationale

Option A preserves the approved baseline sequence while integrating the most useful architecture insights:

- evidence freshness
- official correction / errata tracking
- observation anchoring
- version tracking
- extreme-event update potential
- claim confidence evolution readiness
- runtime re-anchoring readiness

It avoids premature runtime implementation and avoids converting the runtime-integrity layer into a separate operational program.
