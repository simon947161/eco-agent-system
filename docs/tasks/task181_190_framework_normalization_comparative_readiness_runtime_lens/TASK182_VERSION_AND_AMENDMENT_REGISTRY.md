# Task182 Version And Amendment Registry

## Purpose

Task182 defines version and amendment metadata for the framework families discovered in Task171-180.

This registry records visible lifecycle signals. It does not decide which version applies to any real entity, claim, project, disclosure, inventory, or jurisdiction.

## Version And Amendment Fields

| Field | Meaning |
| --- | --- |
| Current visible signal | Version, cycle, page update, effective period, or dated-source signal visible during intake. |
| Previous version | Earlier version, cycle, draft, exposure draft, prior standard, or prior cycle where already identified. |
| Revision history | Publication, amendment, consultation, project, database edition, or report-cycle lineage. |
| Amendment mechanism | Official amendment, errata, correction, consultation, project update, reporting-period portal, questionnaire cycle, or notice update. |
| Update frequency | Assessment cycle, annual cycle, reporting-period cycle, amendment cycle, project cycle, or not specified. |
| Document lineage | How source documents relate across time without interpreting content. |
| Freshness gate | Required check before future use. |

## Boundary

Version metadata does not authorize applying a framework version to any real case.
