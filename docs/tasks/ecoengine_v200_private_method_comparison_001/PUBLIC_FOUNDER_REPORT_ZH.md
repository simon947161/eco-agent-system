# Founder公开报告｜旧候选确实跑起来了，但尚不能排预测冠军

V2.1，2026-11-11；Issue151 / Draft PR153。固定新方为PR152 `cf91e4a061341bc33d16400bcf4c6a2c2817aa65`。

这次已按后来核验的Founder授权，在本地主机检查第二个限定范围，并实际运行了带版本标记的旧候选程序。**它能复跑，不再是只有目录或云端回执；但尚未证实它就是你所说的“跳跃方法”。** 不把早期未找到、版本线索和目标方法身份混成一个结论。

完成了7个不同原生输入与3个边界案例，每例重复一次，共20次调用尝试。18次进入核心，16次非空返回；非空返回包含一次边界问题的重复结果，不是16次科学成功。原生输入输出重放完全一致，边界结果在排除路径和耗时后也一致。详细输入、输出、公式、函数、原件hash和运行日志只在本机。

实际发现三个不同问题：缺必填输入时由Python签名抛TypeError；空历史输入在核心出现ZeroDivisionError；非有限坐标仍得到含非有限值的返回。前两者也不应混称为“受控的数据质量拒绝”。原生演示输出的4项PASS没有断言保障，不能直接当作科学测试通过。

另有4次早期启动失败来自**本次辅助记录器**的标准输出兼容问题，修复记录器后原生程序正常运行。这些失败已留存，排除在旧算法失败统计之外。未改旧源文件或隔离副本中的算法。

两端目前没有已证实的同一预测目标、同一真值和等价边界。旧情景评估与新水热守恒推进不应强行相减或比较速度。**没有完成5–12组成对准确率实验，COMPARISON仍为PARTIAL，整体胜负UNKNOWN。** 10个旧端案例和8组既有新端控制不拼凑成对照实验。

[公共门检查](evidence/public-boundary-checks.json)可复跑，源文件hash与冻结基线核对；本轮没有额外轨迹模拟。旧48次公共控制保持原记录；CI回归执行不是一轮新的研究实验。原件内容与执行副本已在本机复核无变化。没有安装新依赖、改系统网络权限、移植算法、合并或部署。受限运行使用进程内网络/写入拒绝与静态依赖检查，不能宣传为整机断网或任意恶意代码的OS级隔离认证。
