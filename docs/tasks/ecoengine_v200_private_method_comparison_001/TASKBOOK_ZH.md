# Issue #151｜EcoEngine v200 与 ClimateOS 耦合中枢对照研究
**V2 简化执行版｜2026-11-11｜取代本文件 V1；以本版为准**

## 目标
请**本地 Windows Codex**只读研究 Founder 私有的 EcoEngine v200，找出旧程序中所谓“跳跃方法”的真实含义，再与 GitHub [PR #152](https://github.com/simon947161/eco-agent-system/pull/152) 的耦合中枢公平复算。旧方法好就说好，差就说差；不可比就说明原因。**不能预设旧法正确，也不能偏袒新版。**

## 第一步：先确认环境，再读旧系统
1. 在**当前运行的 Windows 电脑**确认能够访问 D 盘。优先检查 Founder 指定的 `D:\EcoEngine`；若不存在，再检查 `D:\eco_engine_v200`。只检查这两个候选位置，不做全盘搜索。
2. 若不在 Windows、本地目录不存在或权限不足：简短返回 `HOST_ACCESS_REQUIRED` 和发现的问题，**停止旧方法研究**；不要假装已阅读，也不要自动重试网络。
3. 若能访问，先只读查看项目入口、README/方法说明、与核心计算有关的必要源码、已有测试。不要修改、运行或清理旧目录。
4. 找出“跳跃”方法原始依据：它实际接收什么输入、改变什么状态、按什么条件进行跳跃、输出什么，存在什么限制。如找不到，明确写 `NOT_FOUND`，不要凭术语猜。
5. 发现旧系统包含需要执行的代码时，先检查副作用；只有能够在**本机禁网、只读原件、隔离工作副本**下安全运行时才复算。若不安全，做静态分析并记录不能运行的原因。

## 第二步：做少量真正公平的实验
1. 固定新版基线：PR #152 HEAD `cf91e4a061341bc33d16400bcf4c6a2c2817aa65`。读取并复跑已公开的关键耦合例子；不要修改它的源代码或科学状态。
2. **先判断两套方法是否回答同一个问题。** 如果旧法是“状态搜索/稀疏点跳跃”，新版是“物理守恒求解”，就分任务评价，不能强行算同一种准确率。
3. 选择**5—12个有信息价值的受控测试**：至少有共同任务（如确有共同输入）、旧法原生用例、新版水热耦合用例，以及缺值/尺度错配/极端边界等反例。固定输入、参数和对照条件，保留失败。
4. 对每个可比任务，记录：输入与输出的可比性、数值误差或守恒残差（若有可信基准）、稳定性、运行成本、复现性、优势与不足。没有可信真值就不要宣称预测精度更高。
5. 最终必须直说：**旧法在哪些问题更好、哪些更差；新版在哪些问题更好、哪些更差；哪些不能比较；有什么新发现值得 ClimateOS 借鉴。** 不得为了凑结论杜撰差异。
6. 不做额外万次实验，不新建平台，不安装重型依赖；试验够回答问题就结束。
