# Task216 Knowledge Harvest Integration

## Purpose

Describe how harvested signals may become governed ClimateOS knowledge.

## Knowledge Object

A Knowledge Object is a reviewed unit of reusable ClimateOS knowledge.

It should preserve:

- source
- context
- review status
- maturity
- uncertainty
- Mission relationship
- relationship to existing architecture
- possible evidence or governance route

## Signal Object

A Signal Object is a captured input before it becomes knowledge or evidence.

It should preserve provenance, uncertainty, maturity, and routing state.

## CRP Object

A CRP Object records a climate resilience pattern or related practice, insight, or governance pattern.

CRP Objects may inform ClimateOS knowledge when reviewed, contextualized, and governed.

## Knowledge Maturity

Potential maturity states:

- Raw signal.
- Captured signal.
- Reviewed signal.
- Knowledge candidate.
- Governed knowledge.
- Evidence candidate.
- Architecture candidate.
- Deferred or retired.

## Relationship To Evidence Passport

Knowledge Harvest may produce candidates for future Evidence Passport structures.

Task211-220 does not create operational Evidence Passport records.

## Relationship To Runtime Integrity

Knowledge Harvest supports future Runtime Integrity by preserving source, freshness, uncertainty, and review status before any future runtime use.

This is readiness metadata only.

## Relationship To AEP

Knowledge that implies architecture change should route through the Architecture Enhancement Protocol.

AEP routing is required before knowledge becomes architecture modification.

## Boundary

This document does not create a knowledge database, runtime integrity system, Evidence Passport runtime, automation, or agent workflow.
