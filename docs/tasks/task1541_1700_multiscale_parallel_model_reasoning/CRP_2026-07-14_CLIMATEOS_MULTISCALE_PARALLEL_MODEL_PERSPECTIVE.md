# CRP — ClimateOS 多尺度平行模型观

Date: 2026-07-14

Status: FOUNDER-DIRECTED CONCEPT RECORD / FUTURE-ROADMAP CONTROL

Scope: Task1541–1700 and later external-model intake

## 核心观点

ClimateOS 引入 UniCM 或其他外部理论模型，不是为了寻找一个最终真理模型，也不是为了把外部模型直接变成 ClimateOS 的中心依赖。

每一个模型都应被理解为一个平行的计算世界。这个世界由自身的变量、空间尺度、时间尺度、边界条件、数据历史、损失函数、机制假设和遗漏共同构成。

ClimateOS 可以相信模型执行了它所声明的计算，但不能因此无条件接受模型对现实世界的解释。ClimateOS 必须阅读计算，而不是服从计算。

## Founder 原意

Founder 提出的工作方法可以概括为：

- 阅读外部模型的计算路线；
- 理解模型采用的观察尺度、观察角度和观察结构；
- 识别模型的边界、局限和优点；
- 不被模型自身的问题定义和尺度限制困住；
- 从模型中寻找与 ClimateOS 问题具有合理类比关系的机制和推动力；
- 将可迁移的优点纳入综合判断，同时保留差异、不确定性和人类责任。

Founder 使用的尺度示例包括 Sydney、Alice Springs、Shanghai 和 Karamay。它们提示 ClimateOS：国家、洲或大区域通常不是足够具体的单一科学观察单位；城市、区域和地点也不能因为表面相似就被视为等价。

## 平行模型观的定义

“平行模型”不是物理宇宙主张，而是一种认识论和工程治理方法。

每个外部模型都是对现实世界的一次有限投影。它可以在自身边界内计算正确，同时在另一个尺度、地点、时期或问题上不适用。

因此，每个模型输出必须与其观察坐标绑定：

1. 空间尺度；
2. 时间尺度；
3. 变量体系；
4. 边界条件；
5. 数据时期与数据制度；
6. 机制类别；
7. 不确定性表达；
8. 被遗漏的机制；
9. 可转译条件；
10. 人类科学责任。

脱离这些坐标的模型数值不得进入 ClimateOS 综合判断。

## 尺度原则

ClimateOS 至少区分：

- planetary：行星与全球系统；
- basin_and_mode：海盆、遥相关和气候模态；
- continental：大陆和大尺度环流背景；
- macroregional：跨州、跨省或气候区域；
- locality_and_city：城市、地方政府区域和具体地区；
- site_and_asset：站点、流域子区、建筑、基础设施或生态斑块。

这些尺度不是简单的高低等级。不同尺度观察到的是不同结构。

从全球尺度得到的关系不能直接下放到地点；从单点得到的经验也不能直接上推到国家或大陆。

任何跨尺度转译都必须声明：

- 聚合或降尺度方法；
- 中间变量；
- 不确定性变化；
- 非平稳风险；
- 缺失机制；
- 适用范围；
- 审查责任。

## 地点类比原则

Sydney 与 Shanghai、Alice Springs 与 Karamay 可以成为候选比较对，但不是预先成立的等价对。

地点类比必须基于机制维度，例如：

- 海洋性与大陆性；
- 纬度、海拔和地形；
- 干旱度和水资源约束；
- 降水季节性；
- 城市热环境；
- 土地覆盖；
- 能源和基础设施结构；
- 社会治理条件；
- 数据可比性。

只有在相关机制维度上形成证据，类比才可进入判断。地名相似、气候标签相似或单一指标相似均不足以建立可迁移性。

## 对 UniCM 的重新定位

UniCM 的价值不主要取决于它能否直接预测某一澳大利亚城市。

它首先是一个可供阅读的计算世界，用于理解：

- 多个气候模态如何交换信息；
- 领先—滞后结构如何形成可预报性；
- 局部状态和全局背景如何共同表达；
- 耦合系统如何产生单一子模型看不到的信息；
- 模型在不同尺度和变量边界下遗漏了什么。

ClimateOS 应提取可迁移的结构思想，而不是把 UniCM 的具体输出或代码结构直接当成 ClimateOS 事实。

## 多模型原则

未来进入 ClimateOS 的天气、水文、生态、土地、能源、建筑、碳和社会经济模型均适用同一规则。

ClimateOS 不预先选择一个永久正确的模型。它必须能够：

- 并列保存多个模型世界；
- 记录每个模型的观察框架；
- 比较模型的一致和冲突；
- 判断冲突是否源于尺度、变量、数据、机制或模型缺陷；
- 保留未解决分歧；
- 将综合判断交由可审查的证据流程和人类责任主体。

模型分歧本身是证据，不应被静默平均或隐藏。

## 架构方向

ClimateOS 的长期能力应从“模型接入中心”提升为“外部模型观察中心”。

建议结构：

现实世界与问题定义
→ Observation Frame Registry
→ 多个外部计算世界
→ Computational Reading Records
→ 跨尺度转译与机制类比
→ External Model Evidence Adapter
→ Environmental Coupling Layer
→ Evidence Passport
→ 人类科学与治理审查

## 关键决策

- Task1541–1700 的中心目标改为建立外部模型阅读、多尺度比较和综合判断能力。
- UniCM 保留为首个深度参考世界，但不再是路线的唯一中心。
- 最小复现只是一种理解模型的方法，不再是路线本身的目的。
- 模型适配器扩大为 External Model Evidence Adapter。
- Environmental Coupling Layer 必须消费带观察尺度和转译记录的证据。
- 澳大利亚试点扩大为多尺度、多地点、机制导向的比较试点。
- AI 数据中心应用轨道保留为候选应用世界，不随本路线自动启动。

## 禁止事项

- 将模型输出脱离观察尺度使用；
- 把相关性、注意力或领先信号直接称为因果；
- 以国家或大陆平均替代具体地点证据；
- 以表面相似建立地点等价；
- 静默消除模型冲突；
- 将研究复现升级为运营预测；
- 让单一外部模型绑定 ClimateOS 核心；
- 绕过 Founder Gate、科学审查或人类责任。

## CRP 结论

ClimateOS 的目标不是找到唯一看世界的方法，而是能够观察不同模型怎样观察世界。

模型观察现实；ClimateOS 观察模型的观察结构；人类审查 ClimateOS 如何形成判断。

这三层责任必须始终分开并留下证据。
