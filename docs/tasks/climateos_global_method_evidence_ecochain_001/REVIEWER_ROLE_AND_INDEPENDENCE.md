# 审查角色和独立性：提案，不是任命

旧ECOChain未查得获批准的审查/审批注册表，故以下不能覆盖旧角色或创造Issuer权限。ISO14064-3/14065/14066仅公开范围与版本核验，不宣称实现付费全文要求。UNFCCC技术审查机制也不向本项目转移授权。

|角色|应承担责任|不可替代的边界|
|---|---|---|
|申报者/数据责任人|授权原件、设备与校准、日期/场址/处理单元、缺测、利益关系、主张及反证|不得挑选通过的输入后隐去失败；对数据真实性负责|
|科学方法技术审查者（新增提案）|核对版本/相态/单位/边界、物料账、计算、出处；列缺口和补证；记录审查范围|不签发碳信用、法定合规或实际效果声明；不能自行批准自己的计算|
|独立核验者|由另行合格且无冲突主体复查原件、抽样、仪表与现场代表性|本轮没有已任命独立现场核验者；UNKNOWN/PENDING|
|方法维护者|维护公式版本、适用域与测试、回应异议；冻结旧版并发布差异|不得用代码修订追溯性地改变旧审批结果|
|Founder批准者|确定项目授权、资源和后续范围；指定正式接纳位置|Founder项目授权不等于政府资质或对真实环境效果的实证|
|AI/规则引擎|建议检查点或输出限定技术检查结果|不是独立核验者；本轮Codex是作者，不能自称ChatGPT已审过本轮|

决策矩阵：技术检查通过且证据不足→补证；方法/数据矛盾→隔离该claim并更正；证据完整→提交另行独立人审；人审通过→仍按授权范围决定下一步；任何法定签发→本轮NOT_PROVIDED，无路由。外部机构认可、现场核验和生产身份验证均未实现。

实际原型的两个role ID为**虚构夹具**，使用不同组织标签检验同人自审、角色冒用和冲突规则。这不是两位真人完成评审，也不证明组织独立性。真实应用前必须取得任命、专业能力、身份、财务/组织关系、COI披露与回避、保密授权和独立决定记录，不能由申报JSON自称即可通过。

技术检查清单：claim逐项范围/反证；来源/合法引用；原始字节与派生代码；单位/气体/相态；时间/空间/仪表位置；校准/不确定性；方法年版；质量账/重复计量；第三方复核范围；结论局限及补证；异议/修订/撤回链。原型执行能力和未来人工职责必须分栏。
