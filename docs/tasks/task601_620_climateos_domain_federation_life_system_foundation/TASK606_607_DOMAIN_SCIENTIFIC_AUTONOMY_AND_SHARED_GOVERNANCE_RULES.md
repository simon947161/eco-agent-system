# Task606-607 Domain Scientific Autonomy And Shared Governance Rules

## Purpose

Define rules that let domains keep scientific autonomy while participating in
shared ClimateOS governance.

## Rule 1: Domain Authority Is Contextual

Each domain owns its specialist interpretation boundaries. ClimateOS may route,
compare, and review evidence, but it should not erase the methods, assumptions,
uncertainties, or review customs of each domain.

## Rule 2: Shared Governance Does Not Equal Shared Scoring

Shared governance means common evidence status, review status, escalation, and
decision logging. It does not mean one universal score across biodiversity,
water, land, carbon, climate, and human governance.

## Rule 3: Cross-Domain Claims Require Traceable Handoffs

A claim that crosses domains must identify:

- originating domain;
- receiving domain;
- evidence objects;
- method or interpretation basis;
- uncertainty;
- review status;
- human reviewer or Founder Gate status.

## Rule 4: Domain Disagreement Is A First-Class Signal

Disagreement between domains is not a failure condition by default. It may show
missing evidence, different time scales, different spatial scales, or competing
governance priorities.

## Rule 5: Private And External Model Boundaries Stay Explicit

Private models, reserved assets, and external scientific tools cannot be
silently absorbed into ClimateOS. Any future use requires explicit permission,
boundary documentation, and validation.

## Rule 6: Human Review Remains Mandatory

No cross-domain record should be treated as decision-ready until a human review
state is present. Automated or model-assisted outputs remain advisory unless a
future authorized system states otherwise.

## Unresolved Questions

- Which review roles are needed for each domain?
- When should disagreement escalate to Founder Gate review?
- What minimum evidence is required before a cross-domain claim becomes
  architecture-ready?

## Current Capability

These are governance rules only. No enforcement engine, workflow automation,
database, API, or scoring system is implemented.
