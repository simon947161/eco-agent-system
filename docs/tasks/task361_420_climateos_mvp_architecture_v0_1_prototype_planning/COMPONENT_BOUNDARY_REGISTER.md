# Component Boundary Register

This document is part of the Task361-420 ClimateOS MVP Architecture v0.1 and Prototype Planning Sprint. It is architecture documentation and prototype planning only. It does not authorize or create runtime, implementation, API, database, MCP, automation, scoring, compliance, assurance, certification, ESG/carbon conclusions, standards interpretation, framework interpretation, operational Evidence Passport, deployment, or Task421.

| Conceptual component | Responsibility | Must not do |
| --- | --- | --- |
| Source Intake | Capture source candidate metadata requirements. | Retrieve sources automatically or admit final evidence. |
| Signal Register | Organize signal candidates. | Assert climate resilience outcome. |
| Claim Candidate Register | Preserve provisional claim candidates. | Validate claims or create conclusions. |
| Knowledge Object Registry Concept | Group linked source, signal, claim, and evidence candidates. | Create database schema or runtime registry. |
| Evidence Candidate Handling | Track evidence candidate limitations and readiness. | Verify, score, certify, or assure evidence. |
| Evidence Readiness Workflow | Represent non-scoring readiness labels. | Rank, score, or automate acceptance. |
| Risk Flag Workflow | Surface stop conditions. | Resolve risk automatically. |
| Human Review Queue | Organize review needs. | Replace reviewer judgment. |
| Founder Gate | Preserve Founder-controlled decisions. | Delegate Founder authority. |
| Audit / Archive | Preserve documentation trail. | Automate GitHub operations. |
| Model Adapter Boundary | Bound model suggestions. | Execute agent actions or decisions. |
